# 所有阶段共用的执行与科研约束

本文件必须与仓库实际 `AGENTS.md` 一起读取。不得以此文件覆盖更高优先级的运行安全约束。

## 1. 增量修改与版本

1. 先读取各级AGENTS、git status、HEAD、README、pyproject、实际目录及目标阶段文件。审查基线仅供比对，禁止reset或回退到旧提交。
2. 保留已有用户修改；不执行git reset --hard、git clean、强制push、删除outputs或修改远程默认分支。除非用户明确要求，不创建PR或推送提交。
3. 不新建另一个工程替代MyAgent。包名仍为eo_agent，现有CLI/API仍通过同一应用服务。
4. 新模式显式开启；旧调用默认legacy，科学模式通过新增选择器进入。新字段默认值保持旧请求可解析；数据库使用追加迁移，不删旧表重建。
5. 不把科研模型写进workflow节点。接口/注册器连接感知、证据和策略。不要同时创建`schemas.py`与同级`schemas/`导致导入歧义。
6. 根目录旧CODEX_PHASE1_PROMPT.md作为历史需求保留，注明其被新方案扩展；不把它继续当作新科学行为定义。

## 2. 科研语义

1. M0—M9映射以DEVELOPMENT_PLAN.md为准；不是简单串联十个固定节点，而有M4—M8事件级回环。
2. 事件类别：stable/persistent_change/transient_change；abstain是决策，不是真值类别。season/reconstruction/registration/SAR/mask是可并存干扰，不和事件类别共用一个softmax。
3. 技术执行状态、证据可用性、模拟状态、科学有效性与校准状态各自独立。
4. 未拟合风险模型不得输出“校准置信度”；允许标注启发式分数，class_probabilities必须为null。未学得动作价值不得冒称expected information gain或Bayes optimal。
5. 没有数据或覆盖不足不等于反证，不等于稳定；不适用不等于技术失败。
6. 派生产物携带根观测ID、时间、空间支持、单位和版本；复制、重采样、模型重算不增加原始测量次数。
7. 精确重复去重；部分同源结果保留并标相关，不使用拍脑袋Jaccard降权声称解决统计依赖。
8. LLM生成的解释不是新数值证据。LLM不能写面积、真实概率、数据源或ground truth；它可以提出命题、对照条件和有限参数计划。
9. 实验前固定承诺并留存hash；执行后允许追加修订版本，但不得覆盖初始预期和参数。
10. 配准/掩膜/替代模型测试称稳健性或对照诊断，不称已经识别了因果效应。

## 3. 数据与模型边界

1. 默认离线，无API Key、无GPU、无影像也能跑。自动测试拦截网络。
2. 真实LLM只在用户显式指定有效profile与网络授权的测试中调用。没有密钥标记未验证；失败不静默换模型或Mock。
3. 密钥不进入日志/报告。记录必要的动作理由、结构输出、工具轨迹，不索取或发布模型隐藏思维链。
4. LLM仅接收白名单序列化的AgentObservationView；不能传完整Settings、TaskRequest、scenario_config或模拟器内部对象。
5. 真值、评分规则、未来实验响应和可泄露标签的场景名留在评测/环境私有区。外部工具、提示词和状态不得读它们。
6. 任务区域、目标月份和数据截止为不可变契约。上下文范围可以在授权域扩展，但不得替换统计范围。
7. 在线动作必须同时检查acquired_at、available_at与产品版本可用性；缺少历史可用性证据时标记不能做严格在线声明。
8. 使用来源标记的逻辑或传播contains_mock。不得为使图表看起来真实而清除；未知来源保持unknown/保守限制。

## 4. 执行与预算

1. 所有动作通过类型、权限、时间、空间、适用条件和预算检查后执行，不执行模型生成的代码、Shell或任意路径。
2. 每次外部LLM尝试前扣预留额度；网络重试、Schema修复和失败逐次写ledger。不事后才拦截超额。
3. 预算分为LLM请求、工具执行、数据读取、计算、回环与时间。不能把重试藏在“1次调用”里。
4. schema合法不代表业务正确；允许有限修复并计入预算，超限返回可诊断终态。
5. 路由函数纯读；状态更新显式节点执行。禁止以消息字符串关键字作为唯一数值判断。
6. 已完成同输入同参数实验可复用产物，但不新增证据；缓存命中、LLM开销和实际读取成本分别记录。
7. 逐步追加轨迹和原子快照；文件保存不等于实现崩溃恢复。恢复能力必须有单独故障注入测试才可声明。

## 5. 验收与交付

1. 每阶段先跑旧测试，新增测试必须证明新行为，不仅检查文件存在。
2. 不删除失败测试、放宽科学断言或固定输出使测试通过。语义变更要记录理由。
3. 每次交付包含变更列表、运行命令、真实输出、未验证项和剩余问题。
4. 未运行的测试写未运行；未训练的模型写未训练；模拟结果仅称流程/契约验证。
5. 更新`docs/hera_progress.md`（阶段状态、决策、阻塞、验证记录）。保存最终有效配置、代码/提示/环境版本。
6. 不给用户承诺后台完成或预估未来耗时。完成当前明确阶段后停止，不自动进入下一阶段。
